## Plain language — why

In wave 2, TASK-14604 moves the calculation's proof (the *manifest*) onto the transactional outbox: it is written to `outbox_events` in one transaction, and a background publisher later copies it into the canonical `events` table. Half of the Regression test fixtures cannot follow that today. Their shared test database has no `outbox_events` table, and their event store is the read-only kind, whose enqueue throws by design. A few facts also rebuild or replay a manifest from `events` straight after a calculation, which only works if something has drained the outbox first; the test hosts run no publisher.

This task prepares all of that **before** the change, while it is still harmless. Today the manifest is not on the outbox, so an extra table, an enqueue-capable store and a drain that finds nothing to drain change no result. It lands in wave 1, is seen green in CI (CI-W1), and is waiting when 14604 arrives.
