## Plain language — why

Each paid month will record its flex balance on its export record: what it opened at, what it closed at, and where the opening came from. This task adds the place to store that, and the optional fields that carry it on the export event, the correction event, the calculation result and the frozen calculation inputs. Everything is additive and optional, so nothing that runs today changes; the payroll task (TASK-14605) fills the fields later. An unused table that once meant to hold the same value is dropped.

## Contract (the WHAT)

1. **Base CREATE of `payroll_export_records`**, after `source` and before the UNIQUE constraint: `opening_balance NUMERIC NULL`, `closing_balance NUMERIC NULL`, `balance_provenance TEXT NULL`, and a named table constraint `payroll_export_records_balances_paired` = all three NULL, or all three NOT NULL **and** `balance_provenance IN ('LEDGER_START', 'CHAINED', 'REHIRE')`. `NUMERIC` **without** a scale, so a stored balance compares exactly with the engine's `decimal` (R-33 item 3). `UNTRACKED` is never stored (R-14 case 3b). Comment block in plain language first (why the columns, why all-or-nothing, why no scale).
2. **Drop `flex_balance_snapshots`** from the base schema (table and both indexes) (R-8).
3. **A new segment** `-- S146-FLEX-LEDGER-SEGMENT-BEGIN` / `…-END`, **after `S138-PROFILE-CATEGORY-NOTNULL-SEGMENT` (`init.sql:5090-5123`), the last segment in the file** (R-34 N2), outside every other marker pair: the three `ADD COLUMN IF NOT EXISTS`; `DROP CONSTRAINT IF EXISTS` + `ADD CONSTRAINT` with identical text; `DROP TABLE IF EXISTS flex_balance_snapshots`; a `DO` block inserting `('s146-flex-ledger', '<plain-language note, incl. "pre-S146 databases are reseeded, not upgraded">') ON CONFLICT DO NOTHING`. Existing rows get all-NULL balances, which the CHECK accepts.
4. **`PayrollExportGenerated`** gains optional `decimal? OpeningFlexBalance`, `decimal? ClosingFlexBalance`, `string? FlexProvenance`. **`RetroactiveCorrectionRequested`** gains optional `decimal? OpeningFlexBalanceUsed`, `decimal? ClosingFlexBalanceBefore`, `decimal? ClosingFlexBalanceAfter`, `string? FlexProvenance`. All `{ get; init; }`, not `required`, documented like `:48-63` (null on raw exports and on every pre-S146 event).
5. **`PeriodCalculationResult`** gains optional `decimal? OpeningFlexBalance`, `decimal? ClosingFlexBalance`, `string? FlexProvenance` (`UNTRACKED` allowed here: it is a result, not a stored record).
6. **`PlanInputs`** gains one **non-positional** optional member, `public string? OpeningFlexProvenance { get; init; }`, not `[JsonRequired]`; absent in a stored record → null (the frozen provenance a replay copies onto its result, R-33 item 2). No positional change. It is **not** part of PCS's `IsComplete` check (`PeriodCalculationService.cs:2253-2260`); TASK-14605 keeps it out.
