## Plain language — why

Every payroll figure is meant to be provable later from its stored *manifest*: the record of how the month was split and which inputs it used. Today the manifest is written in two separate steps on two connections (an event-store append, then a projection row), each in its own try/catch. If both fail, the calculating export still exports, and the correction still writes its event, which then points at a manifest that exists nowhere. The "degraded" flag PCS sets is read by nobody. The project already has one designed way to write a domain event atomically with a state change, the transactional outbox (ADR-018), and Payroll already uses it for its export and correction events. This task moves the manifest onto it: the manifest event, the projection row and the legacy summary event are written in **one transaction**, or not at all, and both routes refuse with 503 before any payroll write when that transaction fails.
