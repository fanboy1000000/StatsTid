## Plain language — why

TASK-14604 moves the manifest onto the outbox behind a new store and changes PCS's constructor. Every test that builds PCS must now hand it a store: an in-memory one for the Unit fixtures (no database), the Postgres one for the Regression fixtures, which TASK-14609 already made able to enqueue. Three Regression facts read the manifest or the legacy event straight from the `events` table, which the outbox fills only after a publisher drains, and the test host removes the publisher; they move to `outbox_events`. Then the new behaviour is pinned: refusal, atomicity (with a positive control, because "no outbox row" is already true today), and the drain.
