## Plain language — why

TASK-14605 removes the "opening balance" argument from every payroll calculation entry point and makes the service derive it from the recorded ledger instead. Every test that passed an opening must stop passing it; every test that builds the service must hand it a ledger reader (or say why it does not need one); and the few tests that really depended on a non-zero opening must now create the situation that produces it: an employed previous month with a recorded closing. Several places in the tests carry a field with the same name that is **not** this argument (what the rule engine received); those stay.
