## Plain language — why

These tests pin two things S144 built. First, the worklist marks a month that cannot be recalculated in the system. Second, the server then refuses the "Recalculated" answer (409) and stamps which block was in force. They seeded that state with a **profile change inside the month**, which blocked the month before Stage B. After TASK-14521 a profile change no longer blocks: such months are payable. So the seeds move to the one case that still blocks, **an agreement change in the middle of a week**, and the expected id becomes the residual's. What the tests prove (the gate, the stamp, the event, the audit row) is unchanged.
