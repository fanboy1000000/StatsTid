# TASK-14516 — the Skema grid refuses a negative number at entry (ux, A.2)

**Why.** TASK-14507 (R24) makes the server refuse a Skema cell with hours ≤ 0 (400 `skema_cell_hours_not_positive`).
- **Zero and empty cells never reach the server.** The save builder skips cells whose hours are `null` or `0` (`frontend/src/hooks/useSkema.ts:203`).
- **A negative number does reach it.** The grid accepts one: `parseDanishNumber` is a bare `parseFloat` (`frontend/src/lib/locale.ts:14-15`). The cell is sent, the 400 lands in the generic "failed, keep local edits, retry" branch (`useSkema.ts:268-270`), and the page re-queues it from live local state (`SkemaPage.tsx:619-628`). Every later save in that session then carries the bad cell and fails, until the user corrects it.
- **Before S145**, the negative was silently stored and summed, which was worse.

The fix belongs at entry: a negative hours value is not a valid cell value.

**Scope.** `ux` (Sonnet). Files:
- `frontend/src/components/SkemaGrid.tsx`: the cell-input and blur paths, `handleCellInput` `:449-482` and `handleCellBlur` `:502-515`;
- its test file under `frontend/src/components/__tests__/`, extended or new, following FRONTEND.md's test conventions;
- `frontend/src/components/SkemaDayPanel.tsx`, **only if** it has an hours input that feeds the same Skema cell save. Census it first. `:212` is the allocation input and is out of scope unless it feeds `onCellChange`.

Nothing else. In particular, no change to `useSkema.ts`'s status handling: with entry guarded, the 400 is reachable only by API misuse, and the generic branch is acceptable for that.

**Do.**
1. In `handleCellInput`, treat a parsed number `< 0` the way the shipped path treats an unparsable one: no propagation to `onCellChange` (`:482`).
   - Also show the user why. Use the inline cell flag the grid already uses for a blocked entry (the `noBasisCell` pattern, `:445-448`) or the nearest existing equivalent, with a short Danish message, for example "Timer kan ikke være negative".
   - Follow FRONTEND.md for the flag's styling and its accessible text.
2. `-0` parses as `-0 === 0`, so it stays "no entry", as today. Do not flag it.
3. The full-day snap paths (`isFullDayEntry`, `:453-456`, and the blur snap `:505-513`) must not snap a negative into a full day. Guard them with the same `< 0` check.
4. If the census finds a Skema-cell hours input in `SkemaDayPanel.tsx`, apply the same rule there.

**Acceptance.**
- Run `npx tsc --noEmit` and vitest (both green).
- A vitest case shows that typing `-7,4` into a project cell and an absence cell calls no `onCellChange` and shows the flag.
- A case shows that typing `7,4` still propagates.
- A case shows that clearing to empty still propagates `null`.

**RED evidence.** The negative-input cases are RED against today's grid, which propagates `-7.4`. Record the observed RED run.

**Note, not a Do (adjudicated at Step 5a of 14507).** The two quota-422 bodies report `remaining` / `requested` from different baselines:
- pre-lock: Σ new against `used − Σ replaced`;
- in-lock: the delta against the full `used`.

Each is internally consistent. If the grid shows these figures to the user, pick one presentation and declare it. Otherwise leave it alone.
