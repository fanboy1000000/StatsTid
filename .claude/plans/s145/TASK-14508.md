# TASK-14508 — payroll reads its own hours (payroll-integration, A.2)

**Why.** Today the two calculating routes take the month's hours from the request (`Payroll/Program.cs:663-680`, passed through at `:335-344, :477-491`). Nobody sends them in practice. Being handed them made two things impossible: catching a missing context day, and proving a payslip later. Payroll now reads the recorded, current hours itself.

**Paste with:** refinement A3 "Hours" (`:287-308`), R25, TASK-14507's report.

**Facts.**
- The repositories are registered only in the Backend host (`Backend/Program.cs:155-156`). The Payroll host's precedent block is `Payroll/Program.cs:62-105`.
- The quiet-deprecation precedent for an *ignored optional* field is at `:682-690`.
- PCS's public calculate entry points are at `:345, :368, :781, :845`; the replay pair is at `:1138, :1171`.
- The correction service calls the obsolete shim before its transaction (`RetroactiveCorrectionService.cs:210`).
- Compliance's widened read is the window precedent (`ComplianceEndpoints.cs:168-178`).

**Do.**
1. **`IRecordedHoursReader`** (payroll-local, R25):
   - `Task<RecordedHours> ReadCurrentAsync(string employeeId, DateOnly fromInclusive, DateOnly toInclusive, CancellationToken ct)` and `Task<RecordedHours> ReadByEventIdsAsync(string employeeId, IReadOnlyList<Guid> entryEventIds, IReadOnlyList<Guid> absenceEventIds, CancellationToken ct)`;
   - `sealed record RecordedHours(IReadOnlyList<TimeEntryProjectionRow> Entries, IReadOnlyList<AbsenceProjectionRow> Absences)`;
   - `ProjectionHoursReader` implements it over the two repositories' default read and `GetByEventIdsAsync`. **It is the only Payroll type that touches the two repositories** (R25), so the Step-7a census lists it by name.
   - **Registration lives in the same file (R58).** `ProjectionHoursReader.cs` exposes `public static IServiceCollection AddProjectionHoursReader(this IServiceCollection services)`. It registers `TimeEntryProjectionRepository`, `AbsenceProjectionRepository`, and `IRecordedHoursReader` → `ProjectionHoursReader`. The Payroll host's `Program.cs` calls it and never names the two repositories.
     - *Why:* the host's own pattern is a bare `AddSingleton<Repo>()` (`Payroll/Program.cs:62, :80, :105`), and that file also hosts the endpoints (`:304`, `:493`). Allow-listing `Program.cs` in TASK-14514's guard would therefore let an endpoint read the repositories, which is exactly what R25 forbids. This way the guard's allowlist stays one file.
2. **PCS.**
   - An optional `IRecordedHoursReader?` constructor parameter, never silent: any calculation or replay without it throws `InvalidOperationException` naming the registration, **before any read** (R25). That means before the classification fetch, the history and window reads, and the hours read.
   - Every public calculate entry point drops `entries`/`absences`. Once the plan is admitted (the planner's refusal; from TASK-14512 also the week check and the prior-month check — R42's order) and before any rule call, the sole logic entry point reads current rows for `[opening-week Monday − 1, periodEnd]`, maps them to `TimeEntry`/`AbsenceEntry` for both lanes, and keeps the rows as read (TASK-14513 binds and digests them). *(Amended at 14508's return, 2026-10-14, adjudicator Q1: "before planning" was stale. Plan-taking entry points arrive with a plan, and R42 makes the hours read the last admission step.)*
   - **Retire `AssertNoDroppedBoundaryCrossing`** *(added at 14508's return, adjudicator Q2; a fix-up on this branch, QUAL-144's lockstep rule).* The guard was interim until payroll widened its own read (ADR-039 D5b/D8; SPRINT-132:315-320), which this task does. A month-end night shift's post-midnight half, dated `PeriodEnd + 1`, belongs to the next month, whose read starts at `HoursReadStart(next.PeriodStart) ≤ this.PeriodEnd`. Drop it in this month; it is counted in the next. Replace the guard with a short comment at the normalization site that names the pin. Pinned by 14508-T's `MonthEndNightShift_Wed30Sep2300To0200_SeptemberNotRefused_PostMidnightHoursReachOctober` (mutation MU-43: restore the throw).
   - The per-segment lane keeps its date filter (`PeriodCalculationService.cs:612-613`), so context rows change nothing until TASK-14511.

   - The correction service drops its hours parameters.
