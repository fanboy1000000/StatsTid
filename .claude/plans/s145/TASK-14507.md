# TASK-14507 — a Skema save replaces the cell (backend-infrastructure, A.1b)

**Scope.** The files in the ledger row, under `src/Backend/**` and `src/Infrastructure/**` (both inside your definition's scope once named, `docs/AGENTS.md:66-70`). Not: the events, rows or `init.sql` (TASK-14500 merged before you branch); any test; `TimeEndpoints.cs`. The additive route needs no change: its event carries no `Source`, so it is TIME_POST.

**Why.** Today a corrected cell is a second row that every server total counts. The ruled meaning is that a Skema save replaces the cell. This task makes that true in storage and in every reader, and it lands before payroll starts reading these rows.

**Do.**
1. **Stamp the source.** The Skema save stamps `Source = HoursSource.Skema` on every `TimeEntryRegistered` and `AbsenceRegistered` it emits (`SkemaEndpoints.cs:1794-1810, :1872-1888`).
2. **Repositories, `InsertAsync`.**
   - The `source` column comes from `HoursSource.Resolve(event.Source)`.
   - For SKEMA only, mark then insert, inside the caller's transaction: `UPDATE … SET superseded_by_outbox_id = @outboxId WHERE employee_id = @e AND date = @d AND <task_id = @t | absence_type = @a> AND source = 'SKEMA' AND superseded_by_outbox_id IS NULL`, then INSERT. Cells are processed in posted order; the partial unique index is the backstop.
   - **Contract:** a TIME_POST row is never marked and never marks.
3. **Readers (R20).** Both default reads, and the five raw-SQL sites, gain `superseded_by_outbox_id IS NULL`. Add `GetByEventIdsAsync(string employeeId, IReadOnlyList<Guid> eventIds, CancellationToken ct)` to each repository: **unfiltered**, ordered by `outbox_id`, the only read that sees superseded rows (A0 constraint 5).
4. **Backfill (R48): mark, then insert — never insert first.**
   - The backfill reads in stream order (`ORDER BY events.stream_id, events.stream_version`, `ProjectionBackfillService.cs:121`) and inserts each row at once (`:377`).
   - Skema and `POST /api/time-entries` both write to `employee-{id}` (`SkemaEndpoints.cs:1438`; `TimeEndpoints.cs:181`), so one employee's cells are one stream, and stream order **is** `outbox_id` order for every cell.
   - The hazard is insert-then-mark against the partial unique index. So, per event in stream order:
     - for a SKEMA event, first the idempotent `UPDATE … SET superseded_by_outbox_id = @id WHERE <cell matches> AND superseded_by_outbox_id IS NULL AND outbox_id < @id`, then `INSERT … ON CONFLICT (event_id) DO NOTHING`. This is the same mark-then-insert as Do 2.
     - A TIME_POST event is inserted only.
   - It never truncates (`:40-43`), so a re-run against a populated table changes nothing (refinement `:206`).
5. **Signed quota delta (R23, as amended by W1).** Per entitlement type, delta = Σ new feriedage − Σ stored feriedage of the current rows this save supersedes (stored, i.e. after any D4 revaluation).
   - *Pre-transaction:* **only for a type whose delta > 0**, call the rule with `used = balance.Used − Σ superseded` and `requestedDays = Σ new`. A type with delta ≤ 0 gets no quota pre-check. The SENIOR_DAY age-gate call (`:1055-1071`) is unchanged.
   - *In-lock, authoritative:* re-read the predecessors after the lock. Delta > 0 goes through the guarded `CheckAndAdjustAsync`. Delta ≤ 0 goes through an ungated `used = used + delta` in the caller's transaction. *Hint (HOW):* a `(conn, tx)` overload of `AdjustUsedAsync`.
   - A reduction is never refused.
6. **Zero and partial hours (R24).**
   - A Skema cell with hours ≤ 0, entry or absence, is refused with 400. Mirror `RequestValidator.cs:17`'s rule with a plain error body.
  - A Skema **entry** with a null or empty `ProjectCode` is refused with 400 before any write (Step-5a 14500 finding: an explicit JSON `"projectCode": null` passes `required string` and would become a NULL `task_id`; the index is also `NULLS NOT DISTINCT` now as a backstop).
   - **Every cell of a save is validated before any write.** One bad cell fails the whole save with 400, and nothing is written: no event, no projection row, no balance change. The 400 check therefore runs before the advisory lock and the transaction (`SkemaEndpoints.cs:1490-1499`), alongside the existing pre-lock validation.
   - A full-day-only absence cell re-saved at **any positive number of hours other than the full day** keeps today's 422 (`:982-990`, `:1776-1784`).
   - Do not ship the `useSkema.ts:203` one-liner.
7. **Retraction stays possible:** nothing in this design may require an insert to accompany a supersession.
