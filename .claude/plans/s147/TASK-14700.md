## Plain language — why

Each paid month records its opening and closing flex balance, and the next month opens at that closing. When a correction changes a month's closing, every later month that was built on it is out of date until it is recalculated, one by one. Today payroll checks only the month directly before the one it pays, so a stale month **further back** goes unnoticed and a later month opens on a figure that is wrong. After this task, payroll checks the employee's whole recorded chain before it pays a month, and names the **earliest** month that must be recalculated first. The administrator then recalculates that month, the next attempt names the next one, and so on; a repair never refuses itself. The arithmetic does not change.

## Contract (the WHAT) — R-2 with R-11 … R-14 (transcribed; do not redesign)

1. **One link function that never walks (R-11).** Factor cases 1–4c of today's `Derive` into a public `DeriveLink(X, index, windows)` that reads only X's record, X−1's record, S and the windows. Same outputs as today's `Derive` for every case-1–4c input.
2. **The walk.** `Derive` builds the month index **once** (as at `:138-147`). If M is after S, it walks X **ascending over S < X ≤ P**. For each X that **holds an employed day**, it compares `DeriveLink(X)` with X's recorded `(opening, provenance)`. Then it returns `DeriveLink(M)`.
   - **The earliest X whose link differs** → refuse with the new kind **`payroll-prior-month-stale`**, naming X.
   - **The earliest X whose link itself refuses** → refuse the same way, with the inner kind in the log detail (the exception's diagnostic message).
   - **Cost:** O(n) over the in-memory index; each link evaluated once.
3. **The walk always starts at S (R-12),** even when M's own stretch would open at `REHIRE 0`: "at every export, every recorded month of this employee is consistent with its predecessor".
4. **Skip months with no employed day (R-14).** Such a month keeps the triple it was paid at; it is not compared. Its successor is (it re-derives to `REHIRE 0` against a recorded `CHAINED`, and is named). **S itself is never re-derived** (case 1).
5. **The windows read range (R-13).** `WindowsReadRange(month, ledgerStart)` returns `[min(S, P).start, M.end]` when the records give an S, and today's range otherwise. Both callers already read the records first (`:897` → `:902`; `:942` → `:958`); both use this one helper.
6. **The new kind** `PriorMonthStale = "payroll-prior-month-stale"` beside the others, with a fixed, **date-free** body sentence (the month travels in the `month` member, as today): what is wrong (an earlier month's balance is out of date), what to do (recalculate the named month first), and "nothing was calculated, written or exported".
7. **Where it applies:** both calculating routes, and re-runs and corrections of later months (they all pass through admission and the recheck): 409, the date-free sentence, nothing written. A recalculation of the named month X never refuses itself (every Y < X is consistent by construction).
8. **The class doc** (`:54-57`) is replaced by the guarantee and the repair sequence.
