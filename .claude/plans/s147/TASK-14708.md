## Plain language — why

Skema saves sick days as `SICK_DAY` and the child's sick days as `CHILD_SICK_DAY`, `_2`, `_3`. The calculation's list of absences that count toward the norm spells the child codes `CHILD_SICK_1/2/3` and has no `SICK_DAY` at all, and payroll passes the stored code through unchanged. So in payroll a sick day and a child's sick day each cost a full day of flex, while Skema's screen shows them as neutral. This task makes the stored spelling the one spelling everywhere, classifies every code exactly once (credit, reduction or neutral), refuses an unknown code at the save, and moves the calculation's version marker so an old calculation is never silently replayed under the new reading.

**The sickness rule is now sourced (R1, RR-1).** Under the state working-time agreement (Statens arbejdstidsaftale § 7 nr. 2 and its remark; 022-26, the same text as 014-21), a paid sick day and a child's sick day count with the day's planned hours, never with the hours worked. That settles HK and PROSA. For staff on the AC agreement no central text says so (PAV 19.3.4), so the same rule is applied **as a labelled default by analogy**; the owner confirms it inside the decide track (D-8, question Q-1, lean (a) = this default). So `SICK_DAY` becomes a credit for every agreement StatsTid encodes, and the screen and payroll then agree.
