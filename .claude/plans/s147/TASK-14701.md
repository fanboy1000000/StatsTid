## Plain language — why

Every employee earns five særlige feriedage a year, and the balance shows them, but Skema (the only place absence is registered since ADR-032 D5) has no row to register one. People book ordinary vacation instead, which spends the wrong balance. Everything behind the row already works: the booking, the quota, the valuation and the payroll line. This task adds the row, served only where the agreement configures the entitlement, makes it hideable like every other absence type, and replaces the two duplicated label tables with one.

## Contract (the WHAT)

1. **The row.** `SPECIAL_HOLIDAY_ALLOWANCE` joins Skema's catalogue for every agreement, labelled **"Særlig feriedag"**.
2. **The gate.** It is served only when a `SPECIAL_HOLIDAY` config resolves for the employee's agreement and OK version at the catalogue's anchor (the same dated read the SENIOR_DAY gate uses).
3. **Admin visibility.** The code joins the admin visibility list, so an org can hide it like any other type.
4. **One label map.** The two tables become one shared map (*Hint:* a static `AbsenceTypeLabels` in `src/Backend/StatsTid.Backend.Api/Services/AbsenceTypeLabels.cs`), read by both endpoints. TASK-14708 (wave 2a) later moves the codes to the SharedKernel constants; keep the map keyed by the stored string.
5. **Whole days (R-19).** No change: the guard reads the config flag and SPECIAL_HOLIDAY seeds `false`, matching ADR-032 D3's "brøkdele af dage" (`ADR-032:37`). That is R2's expected verdict. **Only if R2 contradicts ADR-032 D3** does a fix-up (TASK-14701-F) flip the seed — not this task.
6. **The settlement stays dormant.**
