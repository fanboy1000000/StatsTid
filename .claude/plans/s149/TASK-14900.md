## Plain language — why

S149 moves every dependency to its current version: the .NET runtime, the database driver, the JSON writer's host and so on. It must change no behaviour. Some bytes the system **stores** are later hashed, compared as text, or read back by a replay:
- every event in the event store;
- the payroll export's manifest and its content hash, which payroll uses to tell a repeated export from a conflicting one (ADR-034 D1);
- the digests frozen into a month's proof;
- the month's frozen plan inputs;
- two derived ids.

If the new runtime wrote any of these one byte differently, today's tests would not notice. Each of them computes the expected value with the same code it checks, so both sides would move together. **Your task writes the actual bytes down as literals, today, before anything moves.** From then on, any change to those bytes turns a test red.
