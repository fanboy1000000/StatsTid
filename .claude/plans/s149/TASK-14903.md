## Plain language: why

Every request to StatsTid carries a login token, which the backend validates with Microsoft's IdentityModel library. Today the library is 7.1.2, pulled in indirectly through JwtBearer 8.0.8. Wave 3 moves the runtime to .NET 10, and .NET 10's JwtBearer requires IdentityModel 8, so the token library has to move anyway.

This task moves it **first, alone, on .NET 8, owned by the security agent**. If a login breaks or a check loosens, the token library is then the only possible cause.

Wave 0 froze 15 login pins that run the real validation path: L-1 … L-13 with L-5b, plus L-11 for BCrypt (`tests/StatsTid.Tests.Regression/Security/TokenPathPinTests.cs`, `tests/StatsTid.Tests.Unit/Security/PasswordHashPinTests.cs`). **They must all stay green, unedited.**
