## Plain language: why

The frontend's page navigation (the router) is React Router 6, from the `react-router-dom` package. The newest major is **8**, and **v8 removed the `react-router-dom` package**: everything is imported from `react-router` instead (DV-5). The move is mostly mechanical, since 54 files import from it.

**It is not only mechanical, though.** React Router 7 switched on several behaviours that v6 offered only as opt-in "future flags", and v8 may add new defaults of its own. StatsTid sets **no** future flags today (`App.tsx:64-66` is a bare `<BrowserRouter>`), so every such default switches on with this move. One matters directly: v7 wraps every navigation in React's `startTransition`. The app loads pages lazily (`App.tsx:1`, `lazy`), so while the next page's code loads, React may keep showing the **old** page instead of the loading fallback. That is a change a user could see.

So this task does two things:
- it moves every reference;
- it **checks every new default against the app**, and reports each one that touches what the user sees or what a test asserts.

**Nothing the user sees may change** without a ruling:
- the same 1405 tests in 122 files pass, with no expected value changed;
- lint, the type checks and the production build stay green.
