## Plain language — why

TASK-14805 makes the overtime compensate route answer 409 and record nothing when its own guarded update did nothing. The only way that happens is a race: two leaders settle the same last hours at the same moment, both pass the "enough hours left?" check, and the second update then finds nothing left. This pass stages exactly that race, deterministically: a balance with 6 hours left, two requests for 6 hours, both made to wait at the update until the test lets them go. The test proves the result the owner was promised: one 200, one 409, and **one** "compensation applied" event in the outbox, not two. Expected values come from the refinement (`REF:366`), never from what the code returns.
