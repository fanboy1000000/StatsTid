## Plain language — why

The 11-hour rest rule lives in two places: the server's check (the authority, which the manager sees) and Skema's own instant warning, shown in the day panel while the employee types, before anything is saved. TASK-14813 taught the server to read the clock periods typed in Skema. This task brings the screen in line and proves the two agree.

**1. A night shift is one shift.** Skema cannot hold 24:00, so a night shift is typed as 22:00–23:59 on one day and 00:00–06:00 on the next. Today the screen sees a one-minute rest at midnight and warns: "Denne registrering giver kun 0,0 timers hvile". From now on the two halves are one shift, as on the server: the screen runs the same algorithm as the engine (shifts joined at midnight, grouped by the day they start, consecutive groups compared). A short rest *after* the night shift is still caught. **Example:** Mette works Tuesday 22:00 to Wednesday 06:00 and starts again Wednesday at 16:00. Today she gets a false 0,0-hour warning. After this task she gets the true one: 10 hours between Tuesday's shift and Wednesday afternoon.

**2. Proved, not promised.** One shared table of rest scenarios (14813-T's JSON file) is judged by the engine in a C# test and by the screen in your vitest. Every row must get the same verdict on both sides. If someone later changes one side and not the other, a test goes red.

**3. Two small fixes to the warnings panel ("Arbejdstidskontrol") under the month:**
- **14a:** the panel becomes one polite live region, so a screen reader reads a changed set of warnings once. Today only the "not checked" notice is a live region, and the breaches beside it are silent.
- **14b:** the notice "Hviletid ikke kontrolleret for N dage" is information, not a breach. It now uses the design system's informational colour (`--color-info`) instead of the amber warning colour. The notice stays (owner ruling R-22): after TASK-14813 it appears only for days whose hours are not yet all on the clock.

**What does not change.** The warning texts. The 11-hour minimum on the screen (the server-served minimum is TASK-14829's). No server call is added: the screen keeps warning instantly on unsaved edits.
