## Plain language — why

TASK-14811 makes children's sick days follow the agreement texts. Which days an employee may register now depends on the OK version (2 days per illness under OK24; from 1 April 2026, 3 days plus a new "call-home" code for the remaining hours of the day the child fell ill). Day 2 and day 3 are the calendar days after day 1, and a weekend day needs no row because nothing is planned on it. There is no yearly limit any more. The call-home hours are paid under the wage code `SLS_0530`, and the engine's version marker moves to `weekly-timeline-v3` because a new paid absence is credited.

This pass proves it with thirteen new facts (eleven for AC-S0-2a … e and i, counting AC-S0-2e's payroll check as two facts, one for the credit and one for the export, as the Orchestrator ruled on 2026-11-11; plus two the adjudication added: every agreement has a payroll mapping for the call-home code, and the year overview serves the per-illness allowance), re-pins the existing tests that encoded the old rules (AC 1 day, HK 2, PROSA 3, one yearly quota, the marker `v2`), and finds every other test that touches these rules. Expected values come from the refinement (pasted in TASK-14811's brief, `REF:267-291`) and the agreement texts, never from what the code returns. It also does the groundwork for the mutation evidence: it runs the local test suites with the call-home code's classification row removed (M-8), with the code reclassified as neutral (M-22), and with its payroll mapping rows removed (M-23), and names every fact that turns red, so the Orchestrator's CI evidence run knows exactly what to expect. M-22 and M-23 exist because M-8 is caught by the save's own gate before it reaches payroll, so on its own it proves neither the credit nor the export half. They run in a CI evidence run of their own (CI-M2b), apart from M-8: M-8 removes the same classification row M-22 changes, and would hide both. Splitting the payroll check into two facts lets each of M-22 and M-23 turn exactly one of them red.
