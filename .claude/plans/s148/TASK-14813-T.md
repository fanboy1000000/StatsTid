## Plain language — why

TASK-14813 makes the server's 11-hour rest check read the clock intervals employees type in Skema. Four things change for a user: a real short rest between two Skema days is now reported (today nothing is); a night shift typed as 22:00–23:59 plus 00:00–06:00 counts as one shift, not as a one-minute rest at midnight; a short rest across a month boundary is reported once, in the month in which it ends; and a day is listed as "Hviletid ikke kontrolleret" only when its project hours are not all on the clock.

This pass proves it and keeps the old tests honest:
- **Six new facts**: the three Docker facts of AC-S0-3a, -3c and -3f run the whole route (a real Skema save, then the compliance GET; -3f across the September–October 2025 boundary), the Unit fact of AC-S0-3b checks the midnight join in the engine directly, and one Unit R fact pins that a day with one non-voluntary entry is not exempt from the rest check.
- **The shared parity table**: one JSON file of twelve rest scenarios, read by a C# fact against the engine (yours) and by a vitest against the screen (TASK-14814's). Both sides must give the same verdict on every row.
- **Three mutations, run locally at your gate**: each breaks one behaviour (the midnight join, the "hours covered" rule, the month-edge pairing) and must turn named facts red, proving the facts can fail. That is how S0-4 keeps the screen's instant warning and the server's check from drifting apart.
- **The re-pins**: about twenty existing facts tested the rest check with clock times on the time entries, which the engine no longer reads. Their clock times move to intervals, with the same expected values, except one fact whose value changes on purpose (a partly clocked day is now listed).

Expected values come from the refinement and this brief (pasted in TASK-14813's brief, `REF:293-325`), never from what the code returns.
