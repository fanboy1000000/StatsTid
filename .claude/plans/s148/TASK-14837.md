## Plain language — why

**What HR gets.** When an HR user opens a person in the "Organisation og medarbejdere" drawer, a new section, below the entitlement fields, shows the person's **overtime regime** and whether they are **on the flex scheme**, as recorded today, and lets HR record a new value from a date. TASK-14836 built the routes; you build the section.

**What it must also get right.**
1. **It offers only what the server accepts.** The regime list is the set the server serves for the person's agreement **on the date chosen in the form** (HK: overtime or exempt; PROSA: overtime or contractual; AC: contractual, discretionary or none), never a hard-coded list: the server checks the regime against the agreement in force on the form's date, so the options come from a read for that date (ruling 26). The date cannot be later than today, nor earlier than the current record's start (TASK-14836's ruling 16). A refusal that still comes back is shown in Danish on its field.
2. **"Missing" is visible, and can be saved.** A person with no regime recorded, or whose recorded value their current agreement no longer allows, shows the regime as missing (HRP-025's surfacing; `PLAN:382`). Every AC person `init.sql` seeds starts that way (TASK-14836's item 9). Flex membership and the regime are two separate HR hand-offs, so HR can record flex membership while leaving the regime missing; only flex needs an answer. Once a regime is recorded, clearing it back to missing is not offered (ruling 26).
3. **One's own record is locked.** The server refuses anyone editing their own facts (TASK-14836, AC-C11b). On one's own record the section's inputs and its save button are disabled and point to the drawer's existing note, `pd-self-lock-note` (TASK-14846; the note already says why: the fields "har betydning for din egen løn"). The link is **merged** with any other description an input has, never overwritten (the S148 wave-5 batch-D brief adjudication, ruling 21).
4. **It does not disturb the drawer.** The section loads and saves on its own (ruling 25); its loading or failure never blocks or fails the drawer's "Gem ændringer".
5. **The start of history is never shown.** The seeded rows start from `0001-01-01`, a technical "since always" anchor; the section never shows that date and sets no earliest date from it (ruling 26).
6. **It says these facts do not yet affect pay**, with the batch-A pay note, imported (ruling 26).

**Worked example.** Lise (LocalHR, STY01) opens Jonas (HK). The section reads `GET …/hr-facts?asOf=2026-11-10`: regime `OVERTIME`, on flex, recorded from Monday 2 March 2026, `liveVersion` 1, allowed `["OVERTIME","EXEMPT"]`. She sets the date to Monday 6 April 2026 (the section reads `GET …/hr-facts?asOf=2026-04-06` for that day's options: Jonas was HK then too, so overtime or exempt), chooses "exempt", "not on flex", and saves: the section sends `PUT …/hr-facts` with `If-Match: "1"` and `{ effectiveFrom: "2026-04-06", overtimeRegime: "EXEMPT", onFlexScheme: false }`, re-reads, and announces it. Opening her own record, Lise sees the section with its inputs disabled. Opening Jesper (`emp001`, AC, seeded), she sees the regime as `Mangler – ikke registreret`, no "fra" date, and can save "on the flex scheme: no" with the regime left missing.
