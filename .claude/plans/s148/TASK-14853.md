## Plain language — why

A local administrator may edit their own organisation's projects. The edit (`PUT /api/projects/{orgId}/{projectId}`) and the deactivation (`DELETE` on the same path) check that the caller is a LocalAdmin of the organisation **named in the address**. They then change the project **by its id alone**, and nothing checks that the project belongs to that organisation. So an administrator of organisation A who writes A in the address and organisation B's project id in the path passes the check and renames or deactivates B's project. A deactivated project vanishes from B's employees' project choices.

The flaw is old (Sprints 7–9, `b0ae6523`). The S148 C2-R4 census found it, and it is registered as **SEC-070** (Medium, A01 Broken Access Control). The owner ruled it fixed in S148, before the sprint's close candidate K. The security invariant is co-equal with domain correctness: one organisation must never be able to change another's data.
