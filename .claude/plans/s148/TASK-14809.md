## Plain language — why

**What "manual hours" are.** In Skema an employee records a working day as clock periods, for example 08:00–12:00 and 12:30–16:00. An older model also let a day carry a bare total with no times, "Tilføj timer" (add hours). The owner dropped the screen for it in S72 (ruling D-B), so no screen has created one since. But the server kept the whole machinery: the save still accepts the number, stores it in its own database column (`manual_hours`), puts it in the event it records, serves it back, and every place that adds up a day's work adds it in. That is the send-for-approval check, the leader's team overview and allocation detail, the year overview, the 24-hour day cap and, since wave 1, the new paid-absence day bound.

**Why it goes now.** The owner's model (ADR-043 D10) makes the clock periods the one source of *when* someone worked. From wave 3 the 11-hour rest check reads them, and later stages pay time-of-day supplements from them. An hour with no clock time cannot be checked for rest or placed in the day. A number nobody can see on screen, added silently to every "worked" total, is also a second, invisible way to make a month balance. So the refinement retires it in full (S0-5, P-10), with a reseed: there is no real data to migrate.

**What changes, in numbers.** Wherever the system computes a day's worked hours, it becomes the clock periods alone. The send check then compares clock hours with the hours booked to projects (AC-S0-5b). Payroll never read manual hours, so no payslip moves (PIN-1 holds).

**What is given up, on purpose.** A caller that still sends a `manualHours` member gets no error: the member is ignored (the refinement's "Not built" for this task, `REF:831`). If those hours were also booked to a project, the send check catches the mismatch, because the clock hours no longer cover them.

**This task is the backend half.** TASK-14810 removes the screen's read-only "Manuelt registreret" line and the frontend's carry-forward; TASK-14809-T re-points the tests.
