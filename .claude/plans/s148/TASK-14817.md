## Plain language — why

The "flex carryover maximum" (in the screens "Maks. flexoverførsel", spelt `flexoverfoersel` / `flexoverforsel` in today's copy) is a setting nothing ever read; S148 retires it (C-7, the owner's P-17). TASK-14816 removed it from the database, the server and the contract, so after the Orchestrator regenerates the client types the screens can no longer compile while they still name it. This task takes it off the four screens that show it, and off the tests that build their fixtures with it:

- the **agreement editor** (an administrator's form for the central agreement): one number field;
- the **position-override page**: one number field in the create form, and the value carried through the edit form;
- the **local profile editor** (an institution's own settings): one row in its list of overridable numbers;
- the **configuration overview**: one table column and one line in a profile's detail view.

**Worked example.** An HK administrator opens the local profile editor. Today it lists "Ugentlig normtimer, Maks. flexsaldo, Maks. flexoverfoersel, Maks. overarbejde pr periode", and saving sends six keys. After this task it lists three numbers and the yes/no field, saving sends five keys, and nothing else on the screen moves. No user loses anything that worked: the value was saved, shown and audited, but never used.
