## Plain language — why

TASK-14809 removes "manual hours", a day total with no clock times that no screen has created since S72, from the database, the recorded event, the save request, the month response and every place that adds up a day's work. From now on a day's worked hours are its clock periods alone.

This pass does three things.

1. **Proves the one behaviour that changes for a user** (AC-S0-5b): the month's send check compares clock hours with project hours and nothing else. The proof uses the only route by which today's code still counts manual hours from outside: a save that sends a `manualHours` member. Today that number is stored and counted; after 14809 it is ignored. So a month where the clock shows 4 hours and the projects 4 hours is sent (today it is refused, because 3,4 invisible hours make the day 7,4), and a month where the projects show 7,4 hours against 4 clock hours is refused (today it passes on those same invisible hours). The second case is what the refinement means by "the send check's equality catches lost hours".
2. **Shows the demo still loads** (AC-S0-5d).
3. **Re-points every existing test that read, wrote or asserted manual hours**, 22 files, without changing what any of them proves, except where the brief lists an expected value as intentional.

Expected values come from the refinement and the brief, never from what the code returns.
