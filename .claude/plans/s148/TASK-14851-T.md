## Plain language — why

TASK-14851 lets HR give a person a new employment profile after the old one was closed, through the profile edit with the header "create only if nothing is there". You prove, each with a test that fails on the code before it (where the edit answers 428 to that header and the "not found" read carries no hints):
- **AC-Q268a:** after a close, the read says a re-create is possible and from when; HR re-creates from a chosen date; exactly one new row, one audit row, one event and one projection row appear; the read then shows the new profile.
- **AC-Q268b:** a re-create is refused while a profile covers today or is scheduled (409); an ordinary edit of a person with no profile still answers 404, never a silent re-create.
- **AC-Q268c:** a date after today, or before the last profile's end, is refused with the nearest date that works; the last profile's end itself leaves no gap; a person who has not started yet is re-created from today; a date before a started person's first day is refused without naming that day.
- **AC-Q268d:** nobody re-creates their own profile (GlobalAdmin included), and a departed person acting on their own record is refused by the scope check first.
- **AC-Q268e:** a person moved to another organisation while HR was saving is refused (SEC-062).
- **AC-Q268f:** the re-create waits for the pay-inputs lock first and holds nothing else.
- **AC-Q268g:** a re-create dated into a month payroll has already recorded puts that month on HR's worklist, with no employment-category trigger.
- **AC-Q268h:** the worked example: closed 16 March, re-created from 25 March: March stays refused, April is paid, and the ordinary edit can then fill the gap so March is paid.
- **AC-Q268i:** after a close that cancelled a scheduled change, a re-create from the chosen date runs open: the cancelled change's leftover row is reopened in the same save with the new values, and the new profile keeps the last real profile's category, never the cancelled change's.
- **AC-Q268j:** a fraction of 0 or below, with four decimals, or too large for the column is refused, on the re-create and the edit; a fraction above 1.000 is still accepted (the agreements know "plustid", work above full time).
- **AC-Q268k:** the "not found" read's body matches its declared contract.
