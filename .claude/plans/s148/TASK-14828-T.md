## Plain language — why

The stack switched the pay path in one go: the Rule Engine computes only with the rules it is handed (14826), payroll hands it the rules in force for each stretch of the month (14827), and the Backend's compliance check, the two "expected hours" figures and the Orchestrator's legacy paths hand it theirs (14828). This pass proves, with the plan's named facts, that **a configuration an administrator publishes now reaches pay and the screens, dated, and that nothing reads a value compiled into the code when the database cannot be read.** It also proves the cases the switch must not change: every demo payslip, the two existing 132.00-hour figures, an employee with no record at the end of the month.

**What each group of facts shows, in plain words.**
- **Pay follows the configuration** (AC-C1a, -1b, -1c, -1k, -2a, -2c, -2m, -2p (3), -13a, -13k (2)): an agreement created only in the database is paid at all; a version published "from" an earlier Monday changes that month; two local-profile versions each pay their own days; a switched-off position override stops applying; a month split by a version, a same-day double publish or a transfer pays each part under its own rules; a recalculation after a past-dated publish pays the new version; a discarded draft never pays.
- **Pay fails closed** (AC-C1d, -1e): when the configuration cannot be read, payroll refuses by name and writes nothing; when the engine is handed no rules, payroll writes nothing.
- **The screens follow it too** (AC-C1f, -1m, -1n): a 12-hour minimum rest in force flags an 11.5-hour rest; the "expected hours" sum each day's configured norm (150.80 h, not 140.80 h, when 37 h becomes 32 h on Monday 16 March 2026), keep the month-end fraction (81.40 h), and still show 162.80 h for someone with no record at month end; a configuration outage is an error, not a guessed value.
- **The composed stack** (BC-P5, BC-P6): the smoke suite's direct engine call carries its rules, and the hops this sprint changed (overtime governance, the Orchestrator's two engine paths, compliance, payroll) each get a probe that a missing configuration would turn red.

**Worked example (AC-C1n (1)).** An HK full-timer, March 2026 (22 weekdays, OK24). An administrator publishes HK/OK24 with a 32-hour weekly norm applying from Monday 16 March 2026. Teamoversigt and the balance page both show **150.80 h** (10 × 7.40 + 12 × 6.40), the figure payroll judges. On the code before the stack both show 140.80 h (22 × 6.40): the active version's norm times every weekday.
