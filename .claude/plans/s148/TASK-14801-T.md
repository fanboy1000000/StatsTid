## Plain language — why

TASK-14801 moves payroll's "one person signed twice" refusal earlier and gives it its own name, `payroll-four-eyes`. Before, payroll calculated the month, stored the calculation's proof (the *manifest*), and only then refused, with the same generic "export conflict" any other clash gets. Now it refuses at *admission*, its first look at the month, before calculating anything; and the late check inside the export transaction, which stays as a guard against a row changed in the meantime, answers with the same new name.

These pins prove both halves: a self-approved month is refused at admission and leaves no proof behind (AC-12b-a); a month whose approval row is changed *after* admission and *before* the export commits is caught by the late check with the same name (AC-12b-b), shown on an ordinary month and on the record-less zero-line month whose late check was a real defect once (R-F1). The existing facts that pinned the old name are re-pinned to the new one, each change labelled. Expected values come from the refinement, never from what the code returns.
