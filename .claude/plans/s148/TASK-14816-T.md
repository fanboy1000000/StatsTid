## Plain language — why

TASK-14816 removes two things nobody uses: a checker for old-style local settings (`ValidateLocalOverride`) and the "flex carryover maximum" setting, from the database, the server, the engine's config and three events. This pass does four things:

1. **Proves the checker is gone** (AC-C6) and **the field is gone from the server side** (AC-C7's part), by a search that finds nothing.
2. **Brings every test that named the field into line**, 49 files today, without changing what any of them proves, except where this brief lists a value as intentional. Most are one line in a test's configuration that TASK-14816 already deleted to keep the build compiling; you confirm those and finish what a pure deletion leaves (a helper parameter nobody passes any more, a sentence that counts "48 members").
3. **Pins two behaviours that do change on purpose.** The screens' contract no longer serves the field (the key-set facts), and an old local setting of that name met by the one-time legacy migration is now dropped and recorded, not migrated.
4. **Shows an old event still reads** (DEP-003): an event recorded before the change, which still carries the member in its stored JSON, must still be readable after it. Example: a `RoleConfigOverrideUpdated` stored with `"flexCarryoverMax": 40.25` reads back with every other value intact, the old member ignored.

Expected values come from the plan and this brief, never from what the code returns.
