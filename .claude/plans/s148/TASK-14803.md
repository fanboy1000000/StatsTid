## Plain language — why

TASK-14802 retires the old time-registration route, `POST /api/time-entries`: employees register time in Skema, and the old route let hours typed as on-call, call-in or travel reach payroll and be paid wrongly. The frontend still holds that route's leftovers: a "Tidsregistrering" page that no menu and no address leads to (it was never routed), its entry form, and the hook function that sends the form to the route. With the route gone they are dead code that would call an address that answers "not found".

This task removes them and regenerates the frontend's typed API client from the new contract, so that the type checker itself knows the route is gone. The hook's *read* half stays, because the read route stays. Nobody sees a difference on screen, because nobody could reach the page.

*Given up:* nothing a user can reach. *Why a separate task:* the backend change alters the API contract, and stacking the frontend on it keeps the main branch's type check green between merges (DV-5).
