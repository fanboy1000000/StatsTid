## Plain language — why

**Since wave 5 the central editors' values reach pay**, each from a dated version: an agreement configuration applies from the day its publish names, and a position override from the day each write names (QUAL-182, ADR-043 D12). The server has enforced the date rules since wave 4: never in the future, never before the version it replaces, and a Monday when a field the weekly calculation reads changes (`AppliesFromValidation.cs:6-23`). **The screens never caught up**: they send no date (so every write means "today"), never show a version's date, and on a mid-week refusal show the server's English text. Until this task, four actions are simply refused on any day but a Monday (the interim the owner was told, O-12 (7), `PLAN:763`). This task makes the screens match the server, under the rule wave 6 ends with: **a screen never offers an action the server refuses.**

**What changes, screen by screen.**
1. **The agreement editor** (GlobalAdmin, `/global/overenskomster/:configId`): the publish asks "applies from" (today by default; no later day offered; no day before the version it replaces); a published version shows its date; an active configuration no longer offers "Arkiver" (the server answers 409 since wave 4: "publish a successor", NR-15), a draft still does; and **every label is tied to its field** (N-7), so a screen reader names each input.
2. **The position-override page** (`/lokal/stillingstilpasninger`): create, edit, switch off and switch on each carry a date with the same limits, and each row shows its date.
3. **A refusal is never a dead end** (NR-P14, NR-P17). When the server refuses a mid-week date because a week-read field changed, the editor offers the nearest Monday that the server would accept: on or before today, and on or after the newest version's date. If none exists, it says which Monday is the earliest possible date.
4. **The edit-person drawer** (NR-P4): since TASK-14820 a move to another institution cannot be dated in the future (`AdminEndpoints.cs:2002-2009`), but the drawer's one date field still offers any date. While the organisation field is changed, it offers no date after today and says why in Danish; with the organisation unchanged, future dates stay (S141's scheduling). **On one's own record the date field stays locked** and linked to the self-lock note, with its helper text hidden (TASK-14846; X7).

**Worked example (AC-C2b (2), case (b)).** The newest published version of HK/OK26 applies from Tuesday 10 November 2026; today is Thursday 12 November 2026. A GlobalAdmin publishes a draft that changes the weekly norm, dated today. The server refuses: "not a Monday", listing Monday 9 November and Monday 16 November (`LocalAgreementProfile.cs:134-148`). The 9th is before the newest version (the server would refuse it again, as `BEFORE_PREDECESSOR`); the 16th is after today (refused as a future date). So the editor offers no date and says the earliest possible date is Monday 16 November 2026. *Case (a):* with the newest version from Monday 2 November 2026 and the same refusal for Wednesday 11 November, the editor offers Monday 9 November 2026.
