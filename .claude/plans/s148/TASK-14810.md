## Plain language — why

**Manual hours are gone from the server** (TASK-14809). A "manual hours" value was a day total with no clock times, left over from a "Tilføj timer" row the owner removed in S72. The screen still carries it in three ways:

- the day panel shows a read-only line, "Manuelt registreret: X t";
- every worked total adds it: the panel's "Arbejdstid i alt", the grid's work row and its "Diff. fra normtid", and the flex card's "Denne måned";
- every work-time save resends the day's stored value, so that a save never wiped it. This is the S72 "R7 carry-forward".

The server no longer serves the value or reads it. After `gen:api` the generated types no longer have it, so the code does not type-check until it goes. This task removes it.

On a freshly reseeded database no day has manual hours, so nobody sees a difference. The one visible change: a day's worked figure is its clock periods, which it already was in practice.

**The second job: the paid-absence alert.** In wave 1, TASK-14804 added a rule: a day's paid absence may not exceed the hours planned for the day minus the hours worked on it. When a save breaks it, the screen shows today's absence-cap alert, which reads, for example:

> "Det samlede fravær for dagen (7,4 t) overstiger normtiden (0 t)"

That is the case of a sick day on a day that already holds 7,4 hours of work. The norm is not 0; the room left after the work is 0. The server's refusal now says why: it carries the planned hours and the worked hours. The adjudicator gave the precise wording to this task (B4). The employee should read what happened, for example "planned 7,4 t, worked 7,4 t, so there is no room for paid absence", instead of a wrong statement about the norm.
