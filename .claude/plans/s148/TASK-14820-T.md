## Plain language — why

TASK-14820 gives each person a dated history of which institution they belonged to, and gives a transfer an "effective from" date with three refusals: no future date, nothing earlier than the start of the person's current row, and nobody moves themselves. Most of that is invisible on a screen, so only tests can show it is right. Five things need proving:

1. **The write has the right shapes.** A move dated after the current row's start closes that row and opens a new one. A second move on the same date changes the row in place. A person created today and moved today ends with two rows: the first institution from the start of history to today, the new one from today. *Why two:* HR may later move the new person's first day back, and those earlier days need an institution (DV-7).
2. **The refusals fire only when the organisation actually changes.** HR's edit drawer sends the organisation on every save. A save that leaves the organisation unchanged must still be able to schedule a future agreement code (S141) and correct an agreement code back before a later move (S138). The second of these needs a mutation to prove, because today's code has no dated row to be "before".
3. **Nobody moves themselves**, and moving someone else in the same two institutions still works.
4. **A move dated into the past tells HR**: a month already sent to payroll lands on the worklist with the reason "organisation transfer", and a settled holiday year is flagged. Neither is recalculated.
5. **Every dated read gets the organisation of that day**, and fails loudly when a day has a profile but no organisation. A person created in the product and then backdated still resolves their first institution for the backdated days.

**Worked example (the fixed clock reads Tuesday 10 November 2026).** Ida is in STY01. HR moves her to STY02 from Monday 2 November 2026. Her history then holds STY01 from `0001-01-01` to 2 November and STY02 from 2 November. A second move, to STY03, dated 2 November changes the second row in place. A move dated Monday 26 October 2026 is refused with 400, naming 2 November. A move dated Wednesday 11 November is refused with 400, offering 10 November.

Expected values come from the plan and this brief, never from what the code returns.
