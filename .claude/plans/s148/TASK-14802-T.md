## Plain language — why

TASK-14802 removes `POST /api/time-entries`, an old route no screen uses, through which hours typed as on-call, call-in or travel could be registered and then paid wrongly. It also makes payroll refuse, by name (`payroll-activity-type-refused`), any month that still holds such a stored hour. This pass does two things.

1. **It proves the change.** The route is gone while the read route stays (AC-S0-1a). A month holding a typed hour is refused by both payroll routes and nothing is written, while ordinary months calculate as before (AC-S0-1b). A month already paid still replays exactly as it was paid, but cannot be recalculated while a typed hour sits in it (AC-S0-1c).
2. **It moves every existing test off the route.** Twenty-three test files mention the route. A test that used it only to put hours in the database moves to the Skema save or to a SQL insert, with the same assertion. A test of the route's own behaviour retires, with the reason and the surviving test that covers the same rule on Skema named. The smoke suite, which runs only in CI against the composed stack, posts to the route twice. The security pins for SEC-046 (a departed employee writing time with a still-valid login) were written against this route; they retire or move to the Skema save, and the Orchestrator notes it in the register.

Expected values come from the refinement and the owner's rulings, never from what the code returns.
